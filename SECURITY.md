# Security Policy

## Supported version

Until a stable release exists, only the latest commit on `main` receives security fixes.

## Reporting a vulnerability

Do not include credentials, private email, exploit secrets, or personal information in a public issue.

Use GitHub's private vulnerability reporting feature when it is enabled for this repository. If that feature is unavailable, open a public issue containing only a minimal non-sensitive description and ask the maintainer for a private reporting channel.

Include, when safe:

- affected commit or version;
- capability mode involved;
- impact and required preconditions;
- minimal reproduction using synthetic data;
- suggested mitigation, if known.

Do not access another person's mailbox, retain data, or perform destructive testing. A maintainer will acknowledge a complete report and coordinate disclosure based on severity and reproducibility.
